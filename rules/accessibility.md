# Accessibility Rules

Accessibility is part of UI quality, not a final patch.

## Text and contrast

- Maintain readable contrast between text and its background.
- Do not rely on faint gray text for important information.
- Keep body text comfortably readable at normal zoom.
- Do not communicate status with color alone.

## Keyboard and focus

Interactive controls must be keyboard reachable when the platform supports keyboard input.

Focus states should be clearly visible and should not be removed just because they look different from mouse hover states.

## Labels

- Icon-only controls need an accessible name.
- Inputs need real labels or an equally clear accessible association.
- Error messages should explain what needs to change.
- Links and buttons should describe the action they perform.

## Touch

Touch targets should be comfortable enough to hit without precision. Avoid placing small actions too close together.

## Motion

Respect reduced-motion preferences. Important information should never depend entirely on animation.

## Structure

Use semantic structure whenever the stack supports it. Headings should follow a sensible hierarchy, forms should use proper controls, and navigation should be identifiable as navigation.
